# CEN571StarTracker

## Project Overview
The **CEN571StarTracker** is a hardware-software co-design project focused on implementing a Star Tracker system. Star trackers are critical optical attitude determination devices used in spacecraft navigation. This project explores two main approaches:
1. A traditional feature-based algorithmic pipeline running entirely on the CPU.
2. A modern, machine-learning-driven pipeline utilizing a Convolutional Neural Network (CNN), accelerated onto a PYNQ-Z2 FPGA leveraging High-Level Synthesis (HLS) on Vitis.

## Repository Structure
This repository is primarily split into two parts:
- `src/`: Contains both the CNN-based FPGA-oriented pipeline and the traditional CPU baseline, as well as model training scripts, visualization tools, and HLS C++ sources.
  - `src/ml/scripts/`: Contains the CNN definition (`train.py`), HLS C++ source (`star_tracker.cpp`), and C++ testbench (`star_tracker_tb.cpp`).
  - `src/ml/models/`: Contains the generated network weights, exported as a C header file (`star_tracker_weights.h`) for integration with Vitis HLS.

## Tools & Technologies Used
- **Languages:** Python (model training, hardware interfacing via PYNQ), C++ (HLS kernel design).
- **Machine Learning:** PyTorch (for defining and training the CNN models).
- **Hardware Synthesis:** AMD/Xilinx Vitis HLS (to convert C++ algorithms into RTL hardware IPs), Vivado (for block design and bitstream `.bit`/`.hwh` generation).
- **Hardware Target:** PYNQ-Z2 FPGA Board.
- **Peripherals:** Logitech C270 Webcam (for live inference capture).

## Python Setup
Install the dependencies for the part you want to work on. Use a local virtual environment to ensure isolation, but do not commit your `.venv/` directory to the repo.

```bash
# For the baseline feature-based CPU version
python -m pip install -r Baseline_CPU_version/requirements.txt

# For the ML-based FPGA setup and training tools
python -m pip install -r src/requirements.txt
```

## How to Simulate on CPU
To simulate the hardware acceleration natively on the CPU in software:
1. Navigate to the `src/ml/scripts` directory.
2. Run standard C++ compilation targeting `star_tracker.cpp` and `star_tracker_tb.cpp`. Make sure to define the macro `STAR_TRACKER_USE_FLOAT` (e.g., by passing `-DSTAR_TRACKER_USE_FLOAT` to `g++`). This directs the algorithm to use standard floating-point math for native CPU execution and testing. Alternatively, use the **Vitis HLS C Simulation** feature to verify the behavioral model before synthesis.
3. The testbench (`star_tracker_tb.cpp`) inputs sample test images/data into the HLS C++ kernel and compares the classification outputs against expected results.
4. For Python development, you can run the CPU inference by training the network with `train.py` and running validation entirely using PyTorch in software.
5. To test the software CPU baseline visually with the weights generated by the last training run, run the interactive viewer script:
   ```bash
   python3 ./star_tracker_viewer.py --interactive
   ```

## How to Synthesize for FPGA
To convert the C++ model into an FPGA hardware module:
1. Open **Vitis HLS** and create a new project.
2. Add `src/ml/scripts/star_tracker.cpp` as your design source, and `src/ml/scripts/star_tracker_tb.cpp` as your testbench. Include `src/ml/models` in your include paths so the weights header (`star_tracker_weights.h`) is correctly resolved.
3. Select the PYNQ-Z2 board part (e.g., `xc7z020clg400-1`).
4. **Crucial**: Ensure that `STAR_TRACKER_USE_FLOAT` is **NOT** defined in your Vitis HLS project settings. The design must use fixed-point arithmetic instead of floating-point to be efficiently synthesized into FPGA logic.
5. Run **C Synthesis** to export the RTL.
6. Import the generated IP into **Vivado**, create a block design connecting the Zynq Processing System to your IP (via AXI interfaces, see report), run synthesis and implementation to generate the `startracker.bit` and `startracker.hwh` files.

## Running the FPGA Setup (Deployment)
1. In `./src/ml`, upload the Jupyter notebook named `star_tracker_fpga.ipynb` along with the synthesized `startracker.bit` and `startracker.hwh` files onto your PYNQ-Z2 FPGA's filesystem.
2. Ensure that these files exist within the exact same directory on the FPGA.
3. Plug the Logitech C270 camera into one of the USB ports on the PYNQ-Z2.
4. Run all the cells in order within the Jupyter notebook via the PYNQ web interface. **Stop executing at cell 9**, which activates the live camera output.
5. Point the Logitech camera at your test star images to receive live classification outputs from the FPGA hardware.

## Notes
- `src/ml/models/star_tracker_weights.h` is explicitly tracked because the HLS C++ sources include it directly for compilation.
- Generated training artifacts such as `.pth`, `.json`, and `.npy` files are safely ignored by git and can be regenerated locally via the `train.py` script.
- Notebook checkpoints, Python caches, and build outputs are ignored by default.
